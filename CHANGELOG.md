# Market List — Changelog

A running logbook of every change to `index.html`, newest first.

The version **number** shown at the bottom of the app (e.g. `v0.30`) corresponds to the
entries below. The number is paired in the app with the file's automatic
**last-modified date/time** (shown on hover / in the element's title), so each deployed
build is traceable to both a number here and the moment the file was last saved.

Convention: bump the number by `0.01` for each batch of changes, add a dated row here.

| Version | Date | Changes |

| v1.77 | 2026-08-03 | **The flags on a tile stay on one line.** Urgent and If discounted were emitted as three separate children of the tile, and a large tile lays its children out in a column — so an item that was both took two rows of the tile before its own name even appeared. They are one group now: still a row inside a row-shaped tile, and now a row inside a column-shaped one too. **The top banner is the same height on every page, with its title centred in it.** Measured at 390×844, the Shop bar was 69px tall and the Lists bar 50px, and on both the title sat about 4px above the middle. Two causes, both invisible: every other page's header is 44px because it holds a back button and Lists has none, and the 8px of space meant to separate the header from the location chip was still being reserved on pages where nothing follows it. Both bars are now 60px plus the safe-area inset and the title's centre is the bar's centre. **And the sections in Settings fold.** Appearance, Colour, Top and bottom bars, Category headings, Tiles, Sort, Sound, Smart add, Predictions, Users and History each have a caret; tapping one closes it and it stays closed next time. Everything starts open — this makes Settings foldable, it does not decide for you which parts you never use. |
| v1.76 | 2026-08-03 | **The top and bottom bars are yours to set.** They were the only two surfaces in the app you could not reach — fixed glass, while every other colour had a picker. Each now takes a colour, a transparency and a height, and each is independent of the other. Left alone they are byte-for-byte what they were: the colour is Auto, the transparency is 100 and the height is 0, and in that state nothing is written, so the v1.12 glass recipe is still what paints. Pick a colour and the bar becomes it at your transparency — and the labels on it follow, so a dark bar under a light theme does not go blank. **The category heading is treated as the one-line tile it already looks like**: it always had a tile's padding, corner and 1.5px border and simply painted them transparent, so it now takes a background and a border alongside the text colour it has had since v1.57. The heading in Regulars gets its own three, deliberately separate — it heads what you are *not* buying, and there was no other way to make the two differ. That one is bare text, so it only takes the tile shape once you set a colour: the border width and padding are published as zero until then, and an untouched install does not move by a pixel. **And Settings is regrouped** — Colour is the two page-wide colours, the bars have their own section, and every category-heading control (including Category text, which used to sit in Colour, and Category icons, which sat at the bottom of Tiles) is together under Category headings. Nothing was reimplemented; the rows moved. |
| v1.75 | 2026-08-03 | **Every colour row can now be made darker or lighter, including on Auto.** The Calm switch is gone: it was a one-way pastel filter that could only soften a colour, never take it toward black, and on a row set to Auto it was the only control there was. In its place each of the nine rows carries the Darker/Lighter pair. On a row with a colour chosen it still commits a real hex, exactly as before; on Auto it stores a step count instead and applies it to whatever colour the theme or the category supplies, with the count shown on the button so the row says how far it has been moved. If you had Calm on, that row starts at two steps lighter — an approximation, not the same look: Calm also pushed the saturation around, so a migrated row will read a little more colourful than the pastel it replaces, and it is worth a glance at Settings. **The app also remembers where you had scrolled to on each page**, so going from halfway down Settings to Shop and back returns you to the setting you were adjusting instead of the top. And **the page transition is yours to set**: Page slides in from — Auto (the shipped behaviour, where the direction says which way you moved through Lists · Shop · Settings) or a fixed Left, Right, Up or Down — and Page change speed, from Instant, which turns the movement off, through to Slower. |
| v1.74 | 2026-08-03 | **Adding straight into a category now suggests what to add.** Tapping a category's + opened a box with no help at all — you had to know what to type. It now shows the same ranking the search sheet already uses — the regulars you actually buy first, then the dictionary — filtered to the category being added to, since that is the question being asked ("what goes in Fruit?"), with anything already on the list dropped: this is a list of things to add. Alongside it, **Add from your regulars** is set in the same type as the category labels it heads — 18px, sentence case, the page's own text colour, lined up with them — instead of the small shouting uppercase that made the heading louder than everything under it. And a category with no icon no longer wears a colour dot it does not need: the label carries the colour itself, with the Category text picker still winning when one is set. |
| v1.73 | 2026-08-02 | **The two step controls now say Darker and Lighter.** As bare circles they sat among eleven palette circles and read as two more colours to pick rather than as a step from the one already chosen; the words say what they do. They still wear the colour they would produce, with the label written in whatever contrasts with it, so each button remains its own preview and nothing is lost by labelling it. (For the record: these cannot be put inside the system colour sheet — that is a platform view the page has no access to, which is also why its saved swatches are added and removed by Apple's own gestures rather than by the app.) |
| v1.72 | 2026-08-02 | **Every colour row gains a darker and a lighter step.** Beside the palette, a row that has a colour now shows what that colour becomes one step either way; tapping one adopts it, and the row then offers the next step from there, so a colour can be walked toward white or black a tap at a time. The native overlay always offered the whole gamut, but the lightness axis is the one it makes hardest to walk — a spectrum and a separate brightness slider — and this is that axis on its own. The step is done in HSL, so the hue never moves. The steps appear only on a row that has a colour to shade, so a row on **Auto** is unchanged and an untouched install looks exactly as it did; a colour already at pure black or pure white shows no step in that direction rather than a dead control; and the wallpaper gets the same, which is where this started. |
| v1.71 | 2026-08-02 | **A custom wallpaper colour is now the colour you picked.** Measured, choosing black painted a `#525252→#000000→#3d3d3d` ramp with a photograph blended over it and a third of the paper colour washed on top — three transformations between the picker and the screen, so black came out grey and no colour was ever exact (the ramp even made near-black *lighter*, since it clamped its dark stop). A custom colour is painted flat now, with no ramp, no band and no wash; the five shipped tints keep all three, because they are photographs and the softening is what makes text readable over a picture. The wallpaper swatch previews the flat colour, and the live sample stops painting over the wallpaper while you are choosing it. The **tile and text** pickers were measured as already exact and are unchanged — `#E27B72` painted `rgb(226,123,114)` — the only thing that alters a chosen colour there is **Calm**, which is a visible switch per row. |
| v1.70 | 2026-08-02 | **You can now try several colours in the picker before deciding.** `change` on a colour input is not "the picker closed" — on iOS it fires for every colour chosen inside the still-open overlay, so v1.68's commit-on-change still rebuilt the page mid-pick and threw you back to Settings after the first choice. Nothing commits while the picker is open now: applying a colour is always quiet, and the rebuild waits until the picker is genuinely finished with — dismissed, tapped away from, or ended with the new **Done** on the live sample, which is the one part of the app the overlay does not cover. |
| v1.69 | 2026-08-02 | **A live sample of the list now sits at the top of the screen while you pick a custom colour.** v1.68 stopped the colour overlay being dismissed and made the page's tokens repaint live while you drag, but the Settings page shows swatches rather than tiles, so there was still nothing on screen that showed what a colour actually *does* to the list. A compact sample — a category line and a selected and an unselected tile — is now pinned to the top of the screen while a picker is open, where the platform's overlay does not reach. It is painted entirely from CSS custom properties rather than markup, which is what lets it repaint during a drag when nothing re-renders, and each property falls back to what the real tile shows on **Auto**, so the sample is honest before anything is chosen. |
| v1.68 | 2026-08-02 | **The custom colour pickers now let you explore a colour before committing to it.** A native colour overlay is anchored to the `<input type="color">` it was opened from, and every colour setter ended in a re-render that rebuilds the whole page — which destroyed that input and dismissed the overlay the instant you moved the colour, dropping you back on the Settings page before you could see anything applied. | v1.66 | 2026-08-02 | **The search results wrap instead of scrolling sideways, Save to asks before it overwrites, and My appearance lines up with Use.** Three separate reports said the strip of search matches above the search bar could not be panned on the iPhone, and the last two tuning passes both worked in Chromium — so this one is structural rather than another attempt at the same shape. | v1.65 | 2026-08-02 | **The store chip moves under the count, Calm becomes a real pastel, and the Page swatch reaches the last five pickers.** The **store chip** no longer trails the list name — it reads as a qualifier on the *count* ("12 to buy, at Waitrose"), so it sits centred directly beneath it. The count is absolutely centred inside the banner, so the shop header is two rows now, scoped to its own class because the same `header` rule draws the one-row Lists and Settings banners; the extra row is only spent when a store is actually active. **Calm** is a real pastel at last. The work is done in **HSL** now: the hue is held exactly, most of the saturation is kept, and the lightness is raised, so red comes out at S53/L81 and green at S42/L81. Colours that were never chromatic to begin with — grey, black, white — are only lightened, since forcing a saturation floor onto grey turned it into pale blue. Because a pastel fill and white text is unreadable, a selected **Full** tile's default text colour now follows its fill by luminance instead of always being white, so a dark fill still gets white and nothing changes for anyone not using Calm. Finally the **Page** swatch — match the page's own background — reaches **Colour details**, **Text colour**, **Category text** and both tile **Text** pickers. They could not previously even have understood it: each looked its key up in the palette directly rather than going through the shared resolver, which is exactly why only Background and Border offered the swatch. The resolver takes the palette as a parameter now, and all five go through it. |
